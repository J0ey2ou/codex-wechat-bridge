# 手动验收记录模板

执行前确保 `codex login status` 为 ChatGPT、管理页真实模式，并添加一个无敏感数据的测试目录。每个场景记下任务 ID/审批 ID、时间与手机实际可见情况。以下是验收步骤，不表示已通过。

| 场景 | 操作 | 应看到的结果 |
|---|---|---|
| A 阶段通知 | 在 Bridge 本机 UI 创建“只用文字回答第一阶段完成 / 只用文字回答第二阶段完成”两阶段任务 | 第一阶段完成后微信有通知和唯一审批 ID，第二阶段尚未启动；`/approve ID` 后继续 |
| B 状态 | 执行中发“Codex 现在在做什么？”或 `/status ID` | 先确认接收，再返回开始时间、活动、状态、阶段、事件、操作需求、无依据 ETA 标识 |
| C 继续 | 发“继续当前任务，但不要删除原始文件。” | 复用同项目线程；若正运行则排队；若等待审批则要求审批编号 |
| D 工作消息 | 发“明天下午之前完成项目报告，今天晚上提醒我检查进度。” | 收集窗口后两个待确认事项，询问具体时刻；`/confirmtodo ID 明天 15:00`、`/remind ID 今天 21:00` 后有持久提醒 |
| E 恢复 | 任务执行中停止 Bridge 再启动 | 项目/会话/待办/提醒仍在；未完成执行标 UNKNOWN，队列不自动重放；本机核实后处理 |
| F 账号 | 不设置任何 OpenAI API Key，检查账号与完成文字任务 | App Server 使用现有 ChatGPT 登录；无需 OpenClaw |
| G 权限 | 用未绑定用户发命令、重复发相同审批 ID、转发 `/run` | 未绑定无执行；重复审批被拒；带转发元数据/`/collect` 的内容只作为待办 |
| H 投递 | 临时断网后查询投递记录，恢复网络 | 明确失败退避；不确定发送记录 delivery_unverified，不能宣称手机已收到 |

微信手机实际可见性需要本人观察确认；测试报告应记录“服务端接受”和“本人看到手机消息”两个不同结果。不要把 Mock 界面截图当作真实微信成功证据。
