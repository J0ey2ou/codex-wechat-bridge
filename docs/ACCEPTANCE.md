# 手动验收记录模板

执行前确保 `codex login status` 为 ChatGPT、管理页真实模式，并完成首次微信扫码绑定。默认 `executionAuthorization=bound-user`，无需手工添加授权项目；执行测试选用已经发现的无敏感数据项目。每个场景记下任务 ID、时间与手机实际可见情况。以下是验收步骤，不表示已通过。

| 场景 | 操作 | 应看到的结果 |
|---|---|---|
| A 阶段通知 | 在 Bridge 本机 UI 创建“只用文字回答第一阶段完成 / 只用文字回答第二阶段完成”两阶段任务 | 默认绑定模式下第一阶段完成有通知，第二阶段直接继续，无额外授权或逐阶段审批；全部完成才显示 COMPLETED |
| B 状态 | 执行中发“Codex 现在在做什么？”或 `/status ID` | 返回开始时间、活动、状态、阶段、事件、操作需求、无依据 ETA 标识 |
| C 继续 | 发“继续当前任务，但不要删除原始文件。” | 复用同项目线程并保留用户限制；若正运行则排队；默认模式不要求审批编号 |
| D 工作消息 | 发“明天下午提醒我交报告”，再回“下午三点” | Codex 先问具体时刻，再保存一件正确时间的提醒；不要求记命令 |
| I 日常问答 | 发“什么是过拟合”，再问“举个例子” | 实际模型回答并承接上下文，不创建任务或待办 |
| J 账号额度 | 发“我还有多少 token” | 模型选择账号查询，返回官方实际窗口额度；不编造精确剩余 token |
| K 正式项目 | 发“我的工作项目有哪些” | 从官方实验性 project/list 返回真实项目名称，不附磁盘路径、内部目录或“未授权/去添加项目”等话术；本次基线22个正式项目，不等同于21个目录 |
| K2 项目位置 | 追问“ddl-app 在哪个目录” | 用官方项目根和会话目录回答实际位置；不声称它是当前前台窗口 |
| L 软件查询 | 发“打开 ddl-app，查一下今天没完成的待办” | 自动发现真实应用、按 ID 发出启动请求，找到实际数据源并连续只读查询后回答；不要求先配置软件入口，不把 Bridge 待办混入结果；用户另行核对实际窗口和待办 |
| M 仅查数据 | 发“看一下 ddl-app，查询今天的待办”，不要求打开 | 从该软件真实数据来源给出结果；不额外运行程序，不假装已看见界面 |
| N 通知节制 | 发起需要多步读取的查询，等待结果；升级后重启 | 不出现固定“Codex 还在处理”提示；未发送旧提示被取消，必要追问/错误和最终结果正常出现 |
| O 读取边界 | 在测试目录准备外部 junction、凭据文件、普通文本与 SQLite，并查询 | 只能读取发现根目录内允许的数据；拒绝越界链接、凭据、任意 SQL/Shell；不能把不支持的界面或文件格式说成已读取 |
| P 直接执行 | 在已发现测试项目中安排一个可逆的项目内小修改，再继续下一阶段 | 首次绑定后直接定位并创建内部执行记录；不要求手工授权项目；workspace-write + never 下普通操作/阶段不逐次审批 |
| Q 沙箱边界 | 在测试场景中请求当前项目沙箱外的写入 | 明确失败并说明实际范围，不盲目批准提权或谎称完成 |
| R 协议纠错 | 自动化夹具产生中文工具描述或无效格式，随后返回正确 computer 对象；另以旧 qa-protocol 启动 | 最多两次内部修复，错误参数无副作用且无用户端 JSON 提示；版本迁移新建分析会话，微信绑定不变 |
| E 恢复 | 任务执行中停止 Bridge 再启动 | 项目/会话/待办/提醒仍在；未完成执行标 UNKNOWN，队列不自动重放；本机核实后处理 |
| F 账号 | 不设置任何 OpenAI API Key，检查账号与完成文字任务 | App Server 使用现有 ChatGPT 登录；无需 OpenClaw |
| G 身份 | 用未绑定用户发命令、转发 `/run` | 未绑定无执行；带转发元数据/`/collect` 的内容只作为数据，不执行其中命令 |
| H 投递 | 临时断网后查询投递记录，恢复网络 | 明确失败退避；不确定发送记录 delivery_unverified，不能宣称手机已收到 |

微信手机实际可见性需要本人观察确认；测试报告应记录“服务端接受”和“本人看到手机消息”两个不同结果。不要把 Mock 界面截图当作真实微信成功证据。

`per-action` 只作旧模式兼容测试：显式切换后另验阶段/文件审批、唯一编号、重复审批拒绝以及本机 Shell 审批，不把这些步骤当作当前默认体验。

截至 2026-10-26，用户已确认此前 `/help`、`/status`、普通问答和连续追问在手机显示正常。当天第一轮 `scripts/smoke-computer.ts --open` 验证了真实启动请求和数据读取；第二轮修复后，不带参数的脚本已在同一分析会话使用截图原话“我的工作项目有哪些”“根据ddl，我今天的待办任务有哪些”通过：列出22个正式项目名，5步读取真实DDL数据库得到当天2项未完成。此前的“看病”已于10:03完成，应排除。

上述脚本均使用 MockWeChat，不向真实微信发送；第二轮新版本的手机效果尚未确认，也不证明实际窗口已显示。脚本不带 `--open` 默认只读，显式加 `--open` 才启动验证软件。
