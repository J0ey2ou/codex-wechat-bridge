## 窗口、快捷方式与生效方式

窗口页面的 favicon 和 PWA manifest 都引用原 `/icon.svg`，与 EXE 的目标源相同。启动器本身没有主窗口，不能把浏览器任务栏的图标选择行为当成 EXE 资源已生效的证据。

在默认桌面、公共桌面、开始菜单和任务栏固定项中没有发现名为鲁滨逊/Robinson/codex-wechat 的快捷方式。WMI 与 WScript Shell 的快捷方式解析操作被当前受限环境拒绝，因此无法完整核对重定向目录、改名快捷方式或已安装 PWA 的图标缓存；未修改项目外的快捷方式或清理 Windows 图标缓存。

需要在允许本机编译的受管执行环境完成一次构建，命令如下（不要在当前沙箱反复重试）：

```powershell
node node_modules/typescript/bin/tsc -p tsconfig.json
node scripts/copy-ui.mjs
powershell.exe -NoProfile -File scripts\package-windows.ps1 -UpdateExistingLauncher
```

该流程先产出并自检独立的新包，再尝试只更新旧路径的 EXE 图标，并保留原 EXE 备份；若当前启动器窗口仍打开，会保留新包并停止图标替换，不停止 Bridge 服务。成功后以脚本打印的新包目录和图标校验结果为准。仅换启动器图标无需重启 Bridge；旧 Explorer 或任务栏缓存可能需要关闭并重新打开对应窗口。快捷方式若引用同一 EXE 可自然沿用新资源；显式引用其他 ICO 的快捷方式需单独核对，不能保证自动更新。

**只更新 EXE 不等于运行服务已升级。** 新包包含当前源码中的新建项目功能，但旧 Bridge 仍可能继续运行旧应用；下一节的“构建版本与安全更新”正是为解决这个问题。当前打包版本仍是 0.3.0，同号版本检查不能辨别这两份构建。
